0.2.3 strengthens the runtime and supply-chain contract, expands AI Search ranking, corrects R2 multipart behavior, and aligns the documented network model with the platform's host-routable tenant egress. It is a focused pre-1.0 release for self-hosted operators who need current Cloudflare tooling compatibility and deterministic, verified runtime inputs.

## What's new

- **Workerd-owned compatibility authority.** Tenant compatibility dates and flags are validated by the formally pinned workerd build instead of an open-compute-maintained historical allowlist. The system Worker date remains pinned and reviewed independently.
- **Dedicated AI Search reranking.** AI Search now supports Cohere v2 and generic `/v1/rerank` provider protocols, model catalogs, threshold behavior, score projection, metadata boosting, and bounded rerank pools while keeping the public query surface text-only.
- **Host-routable tenant egress.** General tenant outbound uses one workerd `Network` capability for public, private, loopback, link-local, and metadata IP destinations, with Unix sockets denied. Operators own address restrictions through the host firewall, network namespace, container, or VM.
- **R2 multipart correctness.** S3 preflight uses the required 5 MiB minimum for non-final multipart parts, and SSE-C multipart ETags are treated as provider-opaque values while size and decrypted bytes remain verified.
- **Pinned release payloads.** Workerd and Caddy are now prepared from immutable, checksummed release archives and embedded into `ocd`; repository LFS runtime blobs are no longer the build authority.
- **Current-product Dashboard.** Navigation and product gates are derived from one supported-product inventory, obsolete Browser Run, Containers, and Sandbox stub routes are removed, and large Worker, D1, and Workflow detail views are split into owned components.

## SDK

- Package: `@open-compute/sdk@0.2.3`; install with `npm install @open-compute/sdk@0.2.3` and verify the published version at [npm](https://www.npmjs.com/package/@open-compute/sdk/v/0.2.3).
- Pins: official `cloudflare@7.2.0`, Cloudflare OpenAPI revision `780de88d0324b007c907a1782259b1a0e5e87c7d`, and Wrangler `4.143.0` compatibility fixtures.
- Surface: generated clients continue to delegate every supported operation to the official SDK; the upstream refresh includes the current Worker, Version, Queue, R2, D1, AI Search, Vectorize, Workflow, and observability contracts qualified by this release.
- Pairing: only an `ocd` and SDK with the same stable `X.Y.Z` are qualified together.

## Fixed

- Runtime-source and other platform-owned internal listeners authenticate the generation before reading request bodies; loopback reachability is not treated as authorization.
- R2 provider qualification now exercises a standards-compliant multipart part size and accepts provider-defined SSE-C multipart ETags without weakening content verification.
- AI provider qualification preserves useful sanitized diagnostics and receives the formally pinned Caddy input used by production builds.
- Instance lifecycle control calls use aligned bounded timeouts, and orphan-recovery fixtures wait on deterministic process evidence.
- Wrangler upstream classification, generated capability metadata, and documentation now agree on 4.143.0.
- Release dry-run coverage runs in its owned local Docker harness, and qualification avoids duplicate work while preserving required checks.
- Product documentation and architecture diagrams now describe multi-instance ownership, current egress semantics, supported products, and the formal runtime supply chain consistently.

## Before you upgrade

- No new platform SQLite migration is introduced by 0.2.3. Existing published migration bytes remain unchanged.
- The tenant egress contract is intentionally broader than 0.2.2 documentation described. If your deployment requires public-only or destination-restricted outbound access, enforce that policy with the host firewall, network namespace, container, or VM before admitting tenant traffic.
- Source builds must explicitly prepare workerd and Caddy from `packages/runtime/workerd.lock.json` and `packages/runtime/caddy.lock.json` before `bun run build`. Startup remains offline and never downloads or searches `PATH` for a runtime.
- Compatibility dates and flags are accepted only when the pinned workerd build accepts them. Remove any operator-side assumption that open-compute exposes a smaller fixed historical allowlist.

## Install or upgrade

An existing receipt-managed installation can upgrade directly after taking a backup:

```console
ocd upgrade 0.2.3
```

For a new user-owned installation, download and review the installer, then pin this release:

```console
curl -fsSL -o install.sh https://raw.githubusercontent.com/elliothux/open-compute/v0.2.3/scripts/install.sh
less install.sh
OPEN_COMPUTE_RELEASE_TAG=v0.2.3 sh install.sh
ocd setup --yes
```

Verify with `ocd --version`, `ocd config check`, `ocd instances`, `ocd doctor`, and `ocd capabilities --json` before admitting traffic.

## Security

There are no published security advisories specific to 0.2.3. Platform-owned internal listeners authenticate independently of source address. Tenant general outbound can reach host-routable IP destinations, including private, loopback, link-local, and metadata addresses; the operator must apply any required destination policy outside open-compute. Unix and abstract Unix sockets remain denied, and private Service Bindings continue to use pinned destinations, caller policy, and injected credentials.

## Known limitations

- open-compute does not provide per-Worker or per-instance CIDR or port isolation; use host networking controls when destination filtering is required.
- AI Search public queries remain text-only. Image, file, and multimodal queries fail closed.
- The single-machine deployment profile does not implement Cloudflare's managed multi-region control plane or `workers.dev` service.
- Public Gateway qualification still requires routable TCP 443 and delegated UDP/TCP DNS on the deployment host.
- The macOS document parser has no enforceable hard memory ceiling; concurrency, input/output, CPU, and timeout bounds remain active.
- Code signing and macOS notarization are not included.
